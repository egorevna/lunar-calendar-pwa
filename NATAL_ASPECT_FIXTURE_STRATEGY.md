# NATAL_ASPECT_FIXTURE_STRATEGY.md

## Purpose

This document defines the fixture validation policy for the Sprint 8 natal aspect engine.

The fixture layer validates deterministic math behavior:

- major aspect detection;
- explicit orb boundaries;
- 0 / 360 wrap-around;
- duplicate prevention;
- sorting priority;
- invalid input filtering.

It does not validate birth charts, provider calculations, interpretations, transits, houses, ASC / MC or UI.

## Fixture Principles

Natal aspect fixtures must be deterministic and manually expected.

Allowed:

- synthetic planet longitudes;
- provider-style mock planet objects;
- manually declared expected aspects;
- boundary cases that are obvious from the input longitudes.

Not allowed:

- private user profiles;
- real app user birth data;
- birth charts copied from local storage;
- expected aspect lists generated by the engine under test;
- user-facing display claims.

## Fixture Categories

The required fixture categories are:

- `exactMajorAspects`;
- `nearInsideOrb`;
- `justOutsideOrb`;
- `wrapAround`;
- `duplicatePrevention`;
- `outerOuterNarrowOrb`;
- `luminaryWideOrb`;
- `invalidPlanets`;
- `noAspects`;
- `sortingPriority`.

These categories cover Sprint 8 major-aspect math and regression cases without relying on real natal data.

## Synthetic Data Policy

Fixtures use synthetic planet records only.

Fixture planet records use:

```txt
source: synthetic-fixture
```

The fixture layer must not include:

- `birthDate`;
- `birthTime`;
- `birthPlace`;
- `currentPlace`;
- coordinates;
- profile JSON;
- private names.

## Expected Values Policy

Expected aspect values are manually declared in fixture data.

Examples:

- `Sun 0°` and `Moon 0°` => exact conjunction.
- `Sun 359°` and `Moon 1°` => conjunction with `2°` orb.
- `Mercury 0°` and `Venus 65.1°` => rejected sextile because it is outside the `5°` sextile orb.

The fixture file must not import `src/natalAspectEngine.js` or call `calculateNatalAspects()` to create its own expected values.

## Validation Coverage

The fixture validation layer covers:

- exact conjunction, sextile, square, trine and opposition;
- aspects inside allowed orb;
- aspects just outside allowed orb;
- wrap-around angular distance;
- duplicate A-B / B-A prevention;
- same-body and duplicate-body handling;
- outer-outer narrow orb cap;
- luminary wide orb cap;
- invalid planet filtering;
- no-aspect cases;
- sorting priority.

## What Is Not Covered Yet

The fixture layer does not cover:

- real birth chart reference validation;
- transit aspects;
- aspects to ASC / MC;
- aspects to houses or house cusps;
- aspects to fixed stars;
- aspects to Lilith / Selena / Lunar Nodes;
- aspects to Arabic Parts;
- applying / separating;
- interpretations;
- ritual scoring;
- UI rendering.

## Decision Log

- Fixtures are synthetic and manually expected.
- No private birth data or user profiles are used.
- Expected values are not generated from the engine under test.
- Fixture validation is for math / orb / deduplication / sorting only.
- Natal aspect UI remains a later task.
