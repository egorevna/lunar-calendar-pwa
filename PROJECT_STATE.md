# Project State

Дата чекпоинта: 2026-05-11

## Текущее состояние проекта

Это статическое PWA для iPhone, опубликованное через GitHub Pages:

`https://egorevna.github.io/lunar-calendar-pwa`

Приложение сейчас сфокусировано на одном чистом главном экране для Москвы. Экран можно скроллить вниз, поэтому новые смысловые блоки не нужно насильно помещать в первый viewport.

Дизайн сознательно упрощен: нет верхнего меню, декоративной центральной Луны и нижней навигации. Главный экран должен быть красивым, спокойным и рабочим, без перегруза.

## Что уже реализовано

- Предрасчитанные Swiss Ephemeris данные на 2026-2030 годы.
- Точные лунные дни для Москвы.
- Точные переходы Луны по знакам.
- Луна без курса с интервалами и аспектом, после которого начался VOC.
- Мажорные аспекты Луны к планетам: последний и следующий аспект.
- Точные новолуния и полнолуния с московским временем до секунд.
- Планетарный день и текущий планетарный час.
- Показатели дня:
  - `Индикатор дня` по Tong Shu / `建除十二神`;
  - лунные сутки эзотерической традиции;
  - Ба-цзы день, например `Деревянный Петух`.
- Линия Tong Shu уточнена по документу `Фиксы.docx`: Москва, Jie Qi месяцы, смена энергетического дня в 23:00.
- Блок `Качество поля`: фраза момента, три оценки, причины, списки `Подходит / Не подходит`.
- Влияние прошлого напряженного аспекта Луны ограничено 4 часами после точного аспекта.
- Калибровочный отчет `npm run calibrate:field`.
- PWA-кэш обновлен до `lunar-calendar-v19`.

## Что сейчас работает

- Главный экран показывает дату, день недели, текущее время, лунный день и фазу Луны.
- В день новолуния или полнолуния вместо обычной фазы показывается `Новолуние в HH:MM:SS` или `Полнолуние в HH:MM:SS`.
- Показывается знак Луны и следующий переход Луны в знак с точным временем.
- Показывается статус Луны без курса с точным временем окончания или ближайшего интервала.
- Показывается аспект, после которого Луна ушла без курса, а также последний и следующий аспект Луны.
- Показывается `Качество поля`: краткая фраза, `Интуиция`, `Материальные дела`, `Ритуалы`, причины и практические списки `Подходит / Не подходит`.
- Показываются лунные сутки по эзотерической линии, Ба-цзы день и индикатор дня Tong Shu.
- Показываются планетарный день и текущий планетарный час.
- PWA устанавливается на экран iPhone через Safari.
- Тестовый набор проходит: 24 теста.
- Калибровочный отчет `npm run calibrate:field` выводит контрольные точки для проверки правил `Качества поля`.

## Что не работает или требует уточнения

- Город жестко задан как Москва.
- Нет пользовательских настроек, выбора города, языка или школы расчета.
- Нет дополнительных экранов календаря, планет, знаний и настроек; они сознательно убраны до отдельного проектирования.
- Нет подсказок по нажатию на вопросительные знаки.
- `Качество поля` уже работает технически, но это первая версия интерпретационной модели. Ее нужно калибровать на реальных рабочих днях жены.
- Tong Shu сейчас считается по выбранной линии: ветвь энергетического дня, ветвь Jie Qi месяца и смена дня в 23:00 по Москве. Контрольных дат пока мало.
- Нет автоматической проверки визуального состояния в браузере после каждого изменения.

## Текущий активный фокус

Калибровка блока `Качество поля`: формулировки, веса факторов, списки `Подходит / Не подходит` и причины. Нужно сверить вывод приложения с реальными датами и практикой жены, а не добавлять новые показатели.

## Текущие риски

- `Качество поля` может звучать слишком уверенно, если веса факторов не проверены на реальных кейсах.
- Для Tong Shu есть расхождения между школами и календарями, особенно на стыках суток, солнечных месяцев и часовых зон.
- PWA на iPhone может показывать старый интерфейс из-за Safari/service worker cache.
- Swiss Ephemeris данные сейчас предрасчитаны только до 2030 года включительно.
- Главный экран может снова стать плотным, если добавлять новые объяснения без отдельной версточной проверки.

## С какой задачи продолжать

Продолжать с калибровки `Качества поля`.

1. Прогнать `npm run calibrate:field`.
2. Выбрать 5-10 реальных контрольных дат или моментов из практики жены.
3. Для каждой даты зафиксировать ожидаемые фразу, три оценки, `Подходит`, `Не подходит` и причины.
4. После согласования ожиданий править `src/fieldQuality.js`.
5. На каждый принятый контрольный кейс добавить тест в `test/fieldQuality.test.js`.
